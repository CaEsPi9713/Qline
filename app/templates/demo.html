Antes de empezar (en el servidor)

Deje el entorno en cero para que el primer turno sea A-001. Solo se tocan las claves grupo2:qline:; nunca FLUSHALL.

python scripts/init_mongo.py --recrear --confirmar
python scripts/generar_datos_sinteticos.py --cargar
redis-cli del grupo2:qline:contador:atencion_general grupo2:qline:cola:atencion_general grupo2:qline:ventanilla:V-01:actual grupo2:qline:ventanilla:V-02:actual grupo2:qline:ventanilla:V-03:actual

El primer comando borra y recrea la colección turnos con su JSON Schema; el segundo carga el historial sintético (serie S-).

0 de 10 pasos
  1. Cliente · MongoDB + Redis

    Emitir un turno normal

    Elija Atención Regular y pulse Emitir mi turno.

    Debe verse: el ticket con el código A-001, prioridad normal y estado «En espera».
    Abrir Emitir
  2. Cliente · MongoDB + Redis

    Emitir un turno preferencial

    Vuelva a emitir, esta vez con Atención Preferencial.

    Debe verse: el ticket con A-002 y la insignia «Prioridad Preferencial».
    Abrir Emitir
  3. Cliente · MongoDB + Redis

    Consultar la posición de A-001

    Mongo aporta el estado del turno y Redis su posición en la fila.

    Debe verse: estado Pendiente, 1 turno por delante y posición 2, aunque llegó primero.
    Consultar A-001
  4. Operador · Redis

    Revisar la cola activa

    La cola es un sorted set: la prioridad pesa más que la hora de llegada.

    Debe verse: A-002 (preferencial) en la posición 1 y A-001 en la 2.
    Abrir Cola
  5. Operador · Redis atómico

    Llamar al siguiente desde V-01

    En la cola, elija V-01 y pulse Llamar siguiente. La extracción es atómica: dos ventanillas nunca reciben el mismo turno.

    Debe verse: «V-01 llamó al turno A-002 (preferencial)» y la cola con un solo turno.
    Abrir Cola
  6. Operador · MongoDB

    Iniciar la atención

    En el panel, la tarjeta de V-01 muestra A-002 como «llamado».

    Debe verse: botón Iniciar atención; al pulsarlo el estado pasa a «en atención» y aparece Finalizar atención.
    Abrir Panel
  7. Operador · MongoDB + Redis

    Finalizar la atención

    Pulse Finalizar atención. Mongo registra el cierre y Redis libera la ventanilla.

    Debe verse: mensaje con los segundos de atención y V-01 «Sin turno asignado». Si pulsa el botón otra vez desde una pestaña vieja, el error es controlado.
    Abrir Panel
  8. Supervisor · MongoDB

    Ver el turno en el historial

    El registro de A-002 permanece aunque ya salió de Redis.

    Debe verse: estado atendido, ventanilla V-01, las marcas de tiempo y los segundos de espera y de atención.
    Buscar A-002
  9. Supervisor · MongoDB (aggregation)

    Revisar el dashboard y el SLA

    Cambie la espera máxima (120, 300, 600 s) y observe el cumplimiento.

    Debe verse: turnos esperando (1), atendidos, promedios de espera y atención, ocupación por ventanilla y el % de SLA cambiando con el umbral.
    Abrir Dashboard
  10. Administración · JSON Schema

    CRUD de turnos y validación del esquema

    Abra la colección turnos, intente insertar un documento con "prioridad": "urgente" y luego uno válido.

    Debe verse: el documento inválido es rechazado con un mensaje de validación; el válido se inserta y se puede editar y eliminar (bórrelo al terminar).
    Abrir CRUD turnos
Mensaje técnico: MongoDB conserva el registro de lo que ocurrió; Redis administra la cola activa; y la llamada del siguiente turno es atómica.
