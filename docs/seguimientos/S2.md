#### TT-006 · Conexión Redis · [`app/redis_client.py`](../../app/redis_client.py)

#### TT-007 · Contador y cola · [`app/cola.py`](../../app/cola.py)

| Estructura | Clave | Operaciones |
|---|---|---|
| String | `grupo2:qline:contador:atencion_general` | `INCR` para generar `A-001`, `A-002`, etc. |
| Sorted Set | `grupo2:qline:cola:atencion_general` | `ZADD NX`, `ZRANGE`, `ZPOPMIN` |
| String | `grupo2:qline:ventanilla:{id}:actual` | Turno asignado a cada ventanilla |

**Orden de la cola.** `score = nivel * 10^13 + llegada_ms`, con nivel 0 para preferencial y 1 para normal. La prioridad siempre domina a la hora de llegada y, a igual prioridad, se conserva FIFO. Los valores caben exactos en un double.

**Decisiones de diseño:**
- `ZADD NX` hace que reencolar un código ya presente no lo duplique ni lo reordene.
- La extracción usa `ZPOPMIN`, que es atómico. Dos ventanillas simultáneas nunca reciben el mismo miembro.
- Consultar la cola usa solo `ZRANGE`, que no remueve nada.
- Ventanillas y prioridades inválidas se rechazan con un error controlado.
- No se usa `FLUSHALL` ni `FLUSHDB`.

#### HU-004 · Vista de cola
- Página `GET /cola` con la tabla de posición, código y prioridad, y el conteo de turnos en espera.
- `GET /api/cola` con la misma información en JSON.
- Si Redis no responde, la página muestra un error controlado y la API responde 503.

#### HU-005 · Llamar siguiente · [`app/llamado.py`](../../app/llamado.py)
Redis decide el turno y MongoDB registra el cambio:

1. `ZPOPMIN` extrae el siguiente turno de forma atómica y lo guarda como actual de la ventanilla.
2. En MongoDB, `find_one_and_update` con filtro `estado == "pendiente"` establece `estado = llamado`, `ventanilla` y `timestamps.llamado`.
3. Luego calcula `metricas.espera_seg` a partir de `timestamps.creado`.

| Situación | Respuesta |
|---|---|
| Cola vacía | `ok`, con `codigo: null` y un mensaje. |
| Ventanilla inválida | 400. |
| MongoDB falla después de extraer | 503. El turno vuelve a la cola con su score original, sin perderse ni dejar estados parciales. |
| Turno en Redis que no está `pendiente` en MongoDB | 409. Se descarta de la cola y se libera la ventanilla. |

Interfaces: `POST /api/llamar` (JSON) y el botón **Llamar siguiente** de `/cola`, con selector de ventanilla.

### Qué se implementó

#### TT-001 y TT-002 · JSON Schema e Índices · [`app/turnos_schema.py`](../../app/turnos_schema.py)
- Especificación formal del validador `$jsonSchema` de MongoDB a nivel de colección para `turnos`.
- Restringe campos obligatorios (`codigo`, `servicio`, `prioridad`, `estado`, `timestamps`, `metricas`).
- Restringe prioridades a `normal` y `preferencial`, y estados a los 5 oficiales (`pendiente`, `llamado`, `en_atencion`, `atendido`, `abandonado`).
- Valida que `timestamps.creado` sea mandatorio y tipo `Date` UTC, permitiendo `null` en etapas no alcanzadas.
- Define índices técnicos:
  - `idx_turnos_codigo_unico`: Código único obligatorio (`unique: true`).
  - `idx_turnos_estado_creado`: Consulta eficiente de cola y turnos pendientes.
  - `idx_turnos_ventanilla`: Índice disperso (`sparse: true`) para asignación por ventanilla.
  - `idx_turnos_creado_desc`: Ordenamiento cronológico para auditoría.
- Validador en memoria `validar_documento_turno(doc)` para pre-validación sin conexión activa.

#### TT-004 · Script reproducible de inicialización · [`scripts/init_mongo.py`](../../scripts/init_mongo.py)
- Script ejecutable e idempotente que aplica el validador `$jsonSchema` (con `validationLevel="strict"` y `validationAction="error"`).
- Crea o actualiza la colección `turnos` mediante `collMod`.
- Configura todos los índices necesarios.
- Realiza una auto-verificación insertando documentos inválidos para confirmar que MongoDB los rechace.

#### TT-003 · CRUD administrativo adaptado · [`app/main.py`](../../app/main.py) e [`app/templates/index.html`](../../app/templates/index.html)
- Normalización automática de timestamps ISO a objetos `datetime` UTC al insertar o actualizar turnos.
- Validación preventiva con `validar_documento_turno` para evitar inconsistencias en base de datos.
- Plantilla JSON predeterminada para `turnos` alineada con el contrato oficial.
- Filtro por estado (`pendiente`, `llamado`, `en_atencion`, etc.) en la vista administrativa.

#### HU-010 · Historial y Auditoría · [`app/historial.py`](../../app/historial.py) y [`app/templates/historial.html`](../../app/templates/historial.html)

#### HU-011 · Dashboard y SLA · [`app/dashboard.py`](../../app/dashboard.py) y [`app/templates/dashboard.html`](../../app/templates/dashboard.html)
